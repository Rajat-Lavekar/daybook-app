# Data handling in Daybook 0.2

- App records stay in the iPhone app sandbox. The app itself has no network client, account system, analytics or telemetry. Opening a source article uses your browser and the source website's normal policies.
- iPhone snapshot writes request complete file protection. The data directory is excluded from standard backup. Keep your own encrypted exports; an uninstall can remove local records. There is no extra Face ID app lock in this version.
- The Mac preview uses `private-data/preview/` in this project with private directory/file permissions. It is a development preview, not a sandboxed Mac App Store app. The working snapshot is JSON, not independently application-encrypted; use your Mac's normal account and disk protections.
- HealthKit access is read-only and requests sleep, steps, active energy and workouts. The app caches daily summaries, not raw heart-rate streams or medical records. Revoking Health permissions does not automatically erase already cached records. Missing Health records are not interpreted as zero activity or as proof of refusal.
- The Shortcuts action receives only the text explicitly passed to it. It has no inbox access. It rejects obvious OTP/request templates, stores parsed fields and a fingerprint where a reference is present, and does not retain the full raw SMS body. The supplied bank templates have tests with fictional identifiers. Dates use the bank-reported day when present. Sender authenticity and actual Shortcuts delivery are not verified by parsing a message body.
- GPay PDFs are processed locally using Apple PDFKit. The app saves parsed records, not a copy of the original PDF. The development validation files stay under ignored `private-data/import-validation/`, with private file permissions. No complete statement is automatically included in an AI packet.
- Payment notes from CSV are retained locally. Your added memo is separate. Neither is in an exported finance review packet. Full encrypted backups include both.
- Journal words enter a review packet only if the entry's excerpt switch and that export's excerpt switch are both enabled. Health summaries require their own export switch. Changing a switch cannot retract an already exported file or an already shared chat message.
- An encrypted archive includes all app records and uses AES-256-GCM with a new random 256-bit key for each export. The recovery key is displayed for you to save and is not automatically uploaded or written beside the archive. Without it, the archive cannot be restored.
- Review packets and returned reports are plaintext files. Choosing iCloud Drive or another cloud provider in the system Files picker can sync those files under that provider's settings. Use a private local destination and an intentional transfer if you want to avoid that.
- No phone records are deleted by archival commands. No background collection, AI analysis or recurring task is silently enabled. Local reminders are scheduled only after pressing Enable and approving system notification access.
- Reviews support reflection and record organization. They do not diagnose a mental health condition, establish why a mood changed, or recommend investments. External text is commentary and never executes as an app instruction.

The future archive receipt, deletion, app-lock and schema-migration features in the implementation plan are not present in this build.
